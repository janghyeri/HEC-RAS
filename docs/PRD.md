## F-01 2D 최대 침수심 지도

**PROBLEM**
힌남노 때 냉천 유역에서 "어디가 얼마나 깊게 잠겼는지"를 일반 시민과 수업 관계자가 휴대폰에서도 바로 볼 수 있어야 한다. 하천 범람(외수)만 본 경우와 맨홀 월류(내수)를 더한 경우가 어떻게 다른지도 한 화면에서 바꿔 봐야 한다.

**DATA**
- 입력: `pipeline/export_web.py` 출력 (모형 v1, 시나리오 S0-E 외수 · S0-C 외수+내수)
  - 2 m 최대 수심 래스터(`max_depth_cm.png`, 지형 `Terrain.all.tif` 격자) → 웹 메르카토르 PNG 타일 z12–16 (`pipeline/web_tiles.py`)
  - 셀 격자(`mesh_vertices.i32`, `mesh_offsets.u32`)와 셀 최댓값(`cells_max.u8`): 화면을 눌렀을 때 그 격자의 값
  - 셀 10분 수심(`frames_depth.u8`): 눌렀을 때 시간별 수심 곡선 (처음 누를 때 내려받음)
  - `kpi.json`: 침수면적·침수 시작·깊은 곳 수심(99분위)
  - `manholes.geojson`: 외수+내수의 맨홀 274개 위치
- 배경지도: 브이월드 WMTS (`Satellite` + 지명 `Hybrid`, 일반지도 `Base`), 키 `NEXT_PUBLIC_VWORLD_KEY`. 키가 없으면 OpenStreetMap
- 게시 위치: `web/public/data/<모형 버전>/` (`pipeline/publish_web.py`). 시나리오 목록은 `index.json`에서 읽고 코드에 박지 않는다.

**DOMAIN LOGIC**
- 수심 = 최대 수위 − 2 m 지형 (셀 최저표고 기준 아님, CLAUDE.md 규칙)
- 지도 색은 등급 4개: 0.1–0.5 / 0.5–1.0 / 1.0–2.0 / > 2.0 m (§4.4.1). 0.1 m 미만은 표시하지 않는다. 범례에 사람 키 기준(무릎 0.5 m · 허리 1.0 m · 키 1.8 m)을 함께 적는다.
- 눌렀을 때 값은 그 격자(평균 약 215 m²)의 **젖은 부분 평균 수심**의 최댓값이다. 2 m 화소 색과 다를 수 있으므로 "격자 평균"이라고 표기한다.
- 가장 깊었던 시각 = 셀 수심이 최대인 10분 출력 시각, 0.3 m 이상 지속시간 = 그런 출력 수 × 10분
- KPI 숫자는 `kpi.json` 값을 그대로 쓰고 화면에서 다시 계산하지 않는다. 깊은 곳 수심은 화소 최댓값 대신 침수 화소 99분위.
- 모든 화면에 모형 버전과 "모의 결과이며 실제와 다를 수 있음"을 적는다.

**VALIDATION**
- 타일 위치: 타일을 다시 이어 붙인 모자이크에서 침수 범위 중심이 셀 격자 기준 위치와 2 m(1화소) 안에서 맞는다.
- 타일 면적: z16 타일로 센 0.1 m 이상 면적이 같은 cm 래스터의 면적과 ±1 % 안이다 (재표본 오차). `kpi.json` 래스터 검산값과의 차이도 함께 본다.
- 셀 값: 브라우저 디코딩 결과(0.1 m 이상 셀 수, 최대값)가 파이썬 원자료와 같다.
- 배포 화면: 브라우저 콘솔 오류 0, 브이월드 타일 표시, 시나리오 전환, 휴대폰 크기(375 × 812)에서 지도·범례가 가리지 않는다.
- 하천 중심선·교량이 항공사진과 겹치는지 눈으로 확인 (좌표 변환 확인, §5.1).

**검증 결과 (2026-10-28, 모형 v1)**

| 항목 | 외수 S0-E | 외수+내수 S0-C | 판정 |
|---|---|---|---|
| 타일 면적 / cm 래스터 면적 (km²) | 1.236 / 1.233 (+0.21 %) | 2.809 / 2.804 (+0.17 %) | 통과 |
| 타일 면적 / kpi 래스터 검산값 | +1.25 % | +0.91 % | cm 반올림(0.095–0.1 m 화소 포함) 때문, 설명 가능 |
| 침수 화소 중심점 이동 (타일 vs 원 래스터) | 0.60 m | 0.35 m | 통과 (화소 2 m 안) |

| 배포 화면 콘솔 오류 | 없음 | 없음 | 통과 (위치 기능 경고는 데스크톱 앱 브라우저 한정) |

- 추가로 찾은 것: 10분 수심이 크게 오르내리는 수치 진동 셀(외수+내수 54개, 외수 16개). 화면에서 주의 표시, 처리 방법은 사용자 판단 (docs/GUIDE.md §4.1.5).

## F-04 모의조건 설정·실행

**PROBLEM**
과제 핵심 요구 (1) 모의조건 설정과 (2) 모델 실행을 웹에서 해야 한다 — 정적 대시보드가 아니라 사용자가 바꾼 조건으로 HEC-RAS가 실제로 다시 계산되고 결과가 화면에 떠야 한다. HEC-RAS는 Windows PC에서만 돌고, 그 PC는 외부에서 직접 접속할 수 없다.

**DATA**
- 기준 모형: `C:\Hec-Ras\HECRASMCP\Pohang_web` (모형 v1, 원본은 건드리지 않음). 기준 계획·지형·입력 항목은 `pipeline/models/v1.json` `run`
- 입력 → u01 표: 상류 유입(`Flow Hydrograph`, 하천 경계 1개, 205개 값) · 측방 유입(`Lateral Inflow Hydrograph` 5개) · 맨홀 월류(`Flow Hydrograph`, 2D 경계 274개, 70개 값, 외수+내수만) · 하류 조위(`Stage Hydrograph` 1개)
- 대기열·결과: Supabase `runs`(조건·상태·로그·KPI), `worker_heartbeat`, Storage `results/<버전>/run-<id>/` (kpi.json·셀 값·10분 수심·타일, 1건 약 4 MB)

**DOMAIN LOGIC**
- 배율은 수문곡선 모양을 유지한 채 크기만 바꾼다(값 × 배율). 조위 보정은 하류 수위 곡선 전체에 더한다. 강우를 직접 바꾸지 않는 이유: 모형에 2D 강우가 없고 내수는 맨홀 유량으로 들어감 (가이드라인 §4.3.5)
- 입력 범위(초안): 유입 × 0.5–1.5, 맨홀 × 0–1.5, 조위 0 ~ +1.0 m — **사용자 확정 전**. 맨홀 × 0은 외수 단독 재현 확인용
- 같은 조건(모형 버전 + 기준 + 입력값의 해시)이 이미 계산돼 있으면 다시 계산하지 않는다
- 1D 후처리 끄기(계산 시간 약 4분 단축)는 PC 시험 결과를 보고 사용자가 정한다
- 결과 KPI·지도는 F-01과 같은 정의·변환(pipeline)을 그대로 쓴다. 모든 결과에 model_version을 남기고 비교는 같은 버전끼리만
- 워커 1대 = 한 번에 1건. 대기 작업은 전체 5건, 1인 2건까지. 계산 요청은 로그인한 사용자만 (시민 화면에는 실행 버튼 없음)

**VALIDATION**
- 입력 적용: 실제 u01에 맨홀 × 1.5 → 274개 표 합계가 정확히 1.5배(8칸 반올림 오차 ≤ 5×10⁻⁶ m³/s), 표 밖 줄 변화 없음, 모든 값이 기본값이면 파일이 바이트 단위로 같음 — **통과 (10/30)**
- 완료 판정: 가짜 Ras.exe(돌아온 뒤 백그라운드로 결과를 더 씀)로 대기 논리 시험 — **통과 (10/30)**
- 대기열 권한: 로컬 Postgres + Supabase 역할 흉내로 시험 — 익명 요청 거부, 중복 조건 거부, 1인 2건 제한, 다른 사람 요청 취소 불가, 워커만 작업 가져가기 — **통과 (10/30)**
- 워커 흐름: 가짜 Supabase 서버로 1건 — 상태 순서(준비 → 계산 → 변환 → 업로드 → 완료), 파일 188개 업로드, 잘못된 입력은 'failed'와 이유 기록 — **통과 (10/30)**
- 재현성: 웹에서 배율 1.0 실행 = 보유 결과 (침수면적 ±1 %, 셀 최대수위 차이 99분위 0.02 m) — PC 시험 T1에서 먼저 확인
- 실행: 맨홀 × 1.5 계산 성공, 결과가 지도에 자동 표시, 소요 시간 기록
